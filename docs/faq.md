# 常见问题排查与高级调优 (FAQ)

本章节汇总了在局域网部署、公网云化及物理真机/虚拟机纳管过程中最常遇到的网络连接、触控坐标映射、编解码兼容性与输入控制问题，并提供系统的排错步骤与底层技术原理。

---

## 🔍 问题一：Web 页面加载成功，但提示 WebRTC 连接超时，或一直显示黑屏？

### 📌 可能原因：
1. **UDP 媒体端口未放行**：WebRTC 的前期握手协商通过 WebSocket 信令通道（默认 TCP `8443`）传输。即便信令连接成功，若实际传输音视频的 UDP 媒体端口被防火墙拦截，页面将无法出流。
2. **NAT 协商打洞失败**：客户端与云手机处于严格的对称型 NAT（Symmetric NAT）环境之后，导致 P2P 物理直连打洞失败。
3. **真机编码兼容性问题**：高端物理真机硬件编码器默认输出了 High Profile 等非兼容流，引发网页端 WASM/WebCodecs 解码器黑屏。

### 🛠️ 解决方案：
> [!TIP]
> 推荐优先使用 Host 直连与局域网测试，确认基础连通后再配置公网 NAT 穿透。

* **步骤一：确认高频预览卡片是否正常出流（隔离视频采集与 WebRTC 链路）**
  在大盘监控页面，观察该设备的**高频预览 Canvas 卡片**（或勾选卡片上的“预览直控”模式）是否能够正常看到实时画面：
  * **若高频预览画面正常**：说明 Android 端的 `scrcpy-server` 视频采集、H.264 编码及 WebSocket 二进制传输**完全正常**！问题可 100% 精准锁定在 **WebRTC UDP 媒体通道或 ICE 物理打洞环节**（如 UDP 端口被封禁、NAT 阻断等），请继续按照步骤二至四排查网络。
  * **若高频预览同样黑屏或卡死**：说明 Android 端 `scrcpy-server` 进程未正常启动、系统权限受阻或硬件编码器不兼容，请重点排查步骤五。
* **步骤二：检查防火墙与安全组**
  检查宿主机或云服务器的安全组规则，放行信令端口 `8443` 以及 TURN/WebRTC 媒体使用的 UDP 端口段（例如 `3478` 与 `50000-50100`）。
* **步骤三：指定外网 IP 与端口映射**
  若是 Docker 容器运行，请在 Agent 启动命令行中显式指定宿主机的对外真实 IP 和 UDP 映射端口，以构造有效的 ICE Candidate：
  ```bash
  ./cloudphone-agent -external-addr "<宿主机真实公网/内网IP>" -webrtc-port 50000
  ```
* **步骤四：强制开启 TURN 中继中转**
  若处于复杂对称 NAT 场景，请在一键包启动命令行中传入有效的中转服务配置 `-ice-servers`，强制协商走内置的 `coturn` TURN 中继服务。
* **步骤五：真机 Baseline Profile 兼容性修复**
  物理真机如果连接后黑屏，请在控制界面「设置」->「视频」中将编码 Profile 指定为 **Baseline Profile (`profile=1`)**，并开启 `CP_SEND_CODEC_META=true` 环境变量，强迫手机硬件输出兼容基线流。

## 🔍 问题二：云手机画面投屏正常且极度丝滑，但鼠标点击、改键均无法控制？

### 📌 针对性排错与诊断步骤：

#### 1. 检查国产品牌手机「USB 调试（安全设置）」权限
* 小米（MIUI / HyperOS）、魅族、OPPO 等特定国产品牌手机对安全注入有严格限制。
* **必须**进入手机的「设置」->「开发者选项」，除了开启「USB 调试」外，还必须开启 **「USB 调试（安全设置 - 允许通过 USB 输入）」**。否则 Android 系统会直接丢弃一切外部模拟的 Touch 输入事件。

> [!WARNING]
> 开启「USB 调试（安全设置）」时，部分系统要求手机必须插入 SIM 卡或登录品牌账号，请确保该开关处于激活开启状态。

#### 2. 确认到底为“完全无触控”还是“坐标偏移错位”
* 进入手机「设置」->「开发者选项」，开启 **“显示点按操作反馈”** 与 **“指针位置”**。
* 在网页端用鼠标左键点击设备画面，观察手机物理屏幕上的**真实白色落点轨迹**：
  * **完全无落点**：说明底层系统拦截了输入事件，请重试步骤 1 的权限配置或重启 Agent。
  * **有落点但偏离鼠标**：说明触控坐标映射发生了偏移。

#### 3. 平板与物理横屏设备升至最新版本
* 原生物理横屏设备（如平板、车载大屏、车机云手机等），早期版本曾因高宽物理标尺颠倒导致 `scrcpy-server` 的 `PositionMapper` 匹配失败并直接抛弃事件。
* **最新版本已重构 Canvas 动态标尺与坐标映射算法**，彻底解耦物理高宽限制。请先将控制平台与 Agent 升级至最新版本后重试。

#### 4. 交叉对比测试原生 `scrcpy`
* 使用电脑终端运行原生 `scrcpy` 命令测试触控是否正常。
* 若原生 `scrcpy` 能够正常点击控制，说明手机底层环境与 ADB 权限完全正常，问题通常局限于网页端 Canvas 标尺或分辨率缓存，请尝试点击控制界面的“重置控制比例”或刷新页面。

#### 5. 导出日志提交 Issue 诊断
如果经过上述排查依然无法解决，请协助提取底层调试日志：
1. 在网页端进入「全屏设置」->「高级」，勾选开启 **Agent 调试日志**。
2. 在网页端再次尝试点击控制，复现故障现象。
3. 导出手机中的日志文件：`/data/local/tmp/cloudphone-agent.log`。
4. 请将日志文件、手机具体机型、Android 版本及部署方式（APK 或 agent.zip）提交至 [GitHub Issues](https://github.com/hqw700/ScrcpyOverWebRTC/issues)。

## 🔍 问题三：网页端如何向云手机注入中文/汉字输入？

### 📌 技术原理与用法：
* **技术限制**：Android 系统原生 `InputManager` 底层机制只支持物理 ASCII 字符码注入，无法直接注入中文字符。
* **内置解决方案**：本项目前端构建了 **1px 全透明 textarea 会话管理机制**。在控制界面输入时，拼音合成（Composition）完成后，非 ASCII 字符将自动走静默双向剪贴板通道注入 Android 端系统剪切板并触发组合粘贴，实现 **100% 汉字无感落屏**。

> [!TIP]
> 快捷键提示：在网页控制界面中，直接按下 `Ctrl + V`（或 Mac 下 `Cmd + V`）也可以将电脑剪切板中的长文本静默同步并粘贴至云手机文本框内。

## 🔍 问题四：物理真机在投屏连接后，手机后台频繁响起“叮咚”系统通知声音？

### 📌 解决方案：
* **原因分析**：早期 Agent 在连接时为了保持后台高优先服务，会高频发送系统 Foreground Notification。
* **解决方案**：最新版 Agent 已重构了系统通知逻辑，去除了高频轮询 post 通知，改为单次静默通知，不再产生持续骚音。请升级 Agent 服务端或重新部署最新的 `cloudphone-agent-magisk.zip` / `.apk` 产物即可。

## 🔍 问题五：物理真机长时间挂载投屏发热严重、屏幕无法休眠怎么办？

### 📌 解决方案：
* **开启「息屏连接 (Power Off Screen)」**：
  在控制界面的右侧工具栏中点击「连接设置」，勾选 **“息屏连接”**。
* **效果**：系统在拉起音视频采集和 WebRTC 传输后，会自动切断物理手机的屏幕背光。此时手机物理屏幕处于全黑熄屏状态，但网页端仍可实时流畅观看画面和点击操作。
* **优势**：极大地降低真机硬件功耗与发热，防止屏幕长时间留存静止画面造成烧屏老化，并起到物理防窥作用。
